# 01. Wiki Crawler Skill 설계

## 개요

회사 Wiki(Confluence 기반, konawiki.konai.com)에 접근하여 페이지 내용을 크롤링하고,
LLM이 효율적으로 이해·검색할 수 있는 구조화된 Markdown 문서로 변환하는 스킬.

## 입력

- Wiki 페이지 URL (pageId 포함)
  - 예: `https://konawiki.konai.com/pages/viewpage.action?pageId=422767515`
- 인증 정보: 스킬 내 개인정보 파일에서 읽기 (예: `credentials.yaml`)

## 출력

LLM 최적화된 Markdown 파일. 아래 규격을 따른다.

### 출력 파일 규격

```markdown
# [뉴스 기사형 완전한 제목] | 파일명: xxx.md | 라인: 1-120 | 참조: 3-4
> 출처: [Wiki 페이지 (pageId: xxx)](URL)
> 첨부: [파일명.pdf](다운로드URL)

## 섹션 제목 A | 라인: 5-30 | 참조: 3-4

본문 내용...

## 섹션 제목 B | 라인: 31-60 | 참조: 3-4

본문 내용...

### 하위 섹션 B-1 | 라인: 35-50

본문 내용...
```

**핵심 원칙:**

1. **뉴스 기사형 제목** — 사용자 질문과 시맨틱 비교가 가능하도록 완전한 문장형 제목
2. **헤더에 파일 메타 포함** — h1에는 `파일명`과 `라인 범위`, h2+에는 `라인 범위`와 `참조 라인` 기재. LLM이 헤더만 보고 본문과 출처를 바로 grab할 수 있게
3. **계층 구조** — Wiki 페이지의 구조를 반영한 Markdown heading 계층 (h1 > h2 > h3)
4. **출처/첨부 참조** — h1 아래 1회만 기재, h2에는 `참조: 3-4`로 출처 라인을 가리킴. Python이 본문+메타를 함께 grab 가능. 파일 분할 시에는 각 파일 h1에 포함

## 파일 분할 전략

Wiki 페이지가 클 경우 단일 파일은 LLM 컨텍스트를 낭비한다.
h2 섹션 단위로 파일을 분할하고, **인덱스 파일**로 전체를 조망한다.

### 분할 규칙

- h2 섹션 단위로 분할
- 파일명: `{pageId}_{섹션번호}_{슬러그}.md` (예: `422767515_01_아키텍처.md`)
- 분할 임계값: 섹션 200줄 초과 시 (조정 가능)

### 인덱스 파일

페이지당 인덱스 파일 1개: `{pageId}_index.md`
LLM이 **인덱스만 먼저 읽고** → 필요한 파일만 선택적으로 읽는 2단계 패턴.

```markdown
# 코나 결제 시스템 운영 가이드 (pageId: 422767515)

- **코나 결제 시스템의 전체 아키텍처와 구성 요소** → `422767515_01_아키텍처.md` (85줄)
- **결제 트랜잭션 처리 흐름과 에러 핸들링 방법** → `422767515_02_트랜잭션.md` (120줄)
- **운영 모니터링 대시보드 설정과 알림 규칙** → `422767515_03_모니터링.md` (95줄)
```

### 분할된 개별 파일 규격

```markdown
# 코나 결제 시스템의 전체 아키텍처와 구성 요소 | 422767515_01_아키텍처.md | 라인: 1-85 | 참조: 3-4
> 출처: [Wiki 페이지 (pageId: 422767515)](URL)
> 첨부: [가이드.pdf](다운로드URL)

## API Gateway 구성과 라우팅 정책 | 라인: 5-30 | 참조: 3-4

본문 내용...

## 데이터베이스 이중화 구조와 페일오버 전략 | 라인: 31-85 | 참조: 3-4

본문 내용...
```

## 처리 흐름

```
URL 입력
  → credentials.yaml 읽기
  → Wiki 페이지 HTTP 요청 (Confluence REST API 또는 HTML 크롤링)
  → HTML → 구조화된 섹션 파싱
  → 섹션별 라인수 체크 → 임계값 초과 시 파일 분할
  → 섹션별 뉴스 기사형 제목 생성 (LLM 활용)
  → 헤더에 파일명·라인수 메타 삽입
  → 인덱스 파일 생성
  → 개별 섹션 파일 저장
```

## 미결정 사항

- [ ] Confluence REST API 사용 vs HTML 크롤링 방식 선택
- [ ] 출력 파일 저장 경로 (스킬 내부 vs 별도 디렉토리)
- [ ] 다중 페이지(하위 페이지 포함) 크롤링 지원 여부
- [ ] 기존 파일 업데이트 전략 (덮어쓰기 vs 버전 관리)
- [ ] 분할 임계값 기본값 (200줄 제안)
