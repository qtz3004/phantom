# header-extractor

Markdown 파일에서 `#`, `##`, `###` 헤더 라인만 추출하여 목차(TOC)를 반환한다.
wiki-crawler 출력 파일과 함께 사용하여 LLM 토큰 비용을 절감하는 2단계 읽기 패턴을 구현한다.

## 2단계 읽기 패턴

```
1단계: header-extractor로 헤더만 추출 (토큰 절감)
  → LLM이 헤더의 제목과 라인 범위를 확인
  → 사용자 질문과 관련된 섹션 선택

2단계: 선택된 섹션의 라인 범위로 본문 읽기
  → `라인: start-end` 범위로 해당 섹션만 read
  → `참조: ref_start-ref_end` 범위로 출처/첨부도 함께 read
```

## Instructions

1. 입력으로 파일 경로를 받는다
2. 파일을 읽어 `#`, `##`, `###`으로 시작하는 라인만 추출한다
3. 각 헤더의 라인 번호를 함께 출력한다
4. `> 출처:`, `> 첨부:` 라인도 함께 추출한다 (메타정보)

## 출력 형식

```
[파일명: xxx.md]

L1: # 제목 | 파일명: xxx.md | 라인: 1-50
L3: > 출처: [Wiki 페이지 (pageId: xxx)](URL)
L4: > 첨부: [파일명.pdf](다운로드URL)
L6: ## 섹션1 제목 | 라인: 6-17 | 참조: 3-4
L19: ## 섹션2 제목 | 라인: 19-27 | 참조: 3-4
L29: ## 섹션3 제목 | 라인: 29-32 | 참조: 3-4
```

## 사용 예시

사용자: "고유가 피해지원금 관련 자료 찾아줘"

1단계 — 헤더 추출:
```
header-extractor 실행 → 목차 반환
LLM이 헤더를 보고 관련 섹션 판단
```

2단계 — 섹션 읽기:
```
"## 고유가 피해지원금은 소득하위 70%..." 섹션이 관련됨
→ 라인: 6-17 범위로 본문 read
→ 참조: 3-4 범위로 출처/첨부 read
→ 두 결과를 합쳐서 답변 생성
```
